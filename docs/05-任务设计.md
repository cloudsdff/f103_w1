# 任务设计（FreeRTOS）

> 首次实测：2026-11-16 · F103C8T6 @72 MHz · FreeRTOS 10.x (CMSIS-RTOS2 包装)

## 1. 任务表（实测值，不是估计值）

| 任务 | 优先级 | 周期 | 栈分配 | 实测剩余栈 | 来源 |
|---|---|---|---|---|---|
| `task_led` | `osPriorityBelowNormal1` (17) | 200 ms | 2048 B | 待测 | `osThreadNew()` |
| `task_log` | `osPriorityLow` (8) | 500 ms | 2048 B | **1536 B** | `osThreadGetStackSpace()` |
| `StartDefaultTask` | 默认 | 1 ms | 512 B | — | **CubeMX 遗留，待清理** |

> 栈单位说明：CubeMX 界面里填的是 **512（字）**，生成代码是 `512 * 4 = 2048 字节`。
> 这是本项目的第一个坑——**CubeMX 的 Stack Size 单位是"字"不是"字节"**。

## 2. 系统配置

| 项 | 值 | 备注 |
|---|---|---|
| `configTICK_RATE_HZ` | 1000 | 1 tick = 1 ms，`osDelay(500)` = 500 ms |
| `configMAX_PRIORITIES` | 56 | CMSIS-RTOS2 默认 |
| `configMINIMAL_STACK_SIZE` | 128（字） | 空闲任务用 |
| `configTOTAL_HEAP_SIZE` | **8192** | CubeMX 默认 3072，手动改大（3 个任务栈共 4608 B + 空闲/定时器任务） |
| HAL 计时源 | **TIM4**（1 kHz） | SysTick 让给 FreeRTOS；生成 `stm32f1xx_hal_timebase_tim.c` |
| 调度方式 | 抢占式 | — |

## 3. 资源占用

```
RAM:   13776 B / 20480 B  (67.27%)
FLASH: 23728 B / 65536 B  (36.21%)
```

RAM 67% 的主要来源是 8 KB 的 FreeRTOS 堆。第二周加 CAN/I2C 缓冲时要重新评估。

## 4. 实测证据

串口（COM7 @115200，时间戳为串口助手添加）：

```
===== D2 boot test =====
SYSCLK=72000000 HCLK=72000000 PCLK1=36000000 PCLK2=72000000
task_log cnt=1  stack_free=1544
task_log cnt=2  stack_free=1536
task_log cnt=3  stack_free=1536
...
task_log cnt=16 stack_free=1536
```

三条判据：

1. 时间戳间隔 ≈ **500 ms** → `osDelay(500)` 精确生效
2. `cnt` 逐行 +1 → 任务循环正常
3. `stack_free` 从 1544 降到 **1536 后恒定** → 无栈泄漏，且余量远超 100 B 安全线

LED 由 `task_led` 每 200 ms 翻转一次（肉眼可见比裸机版的 500 ms 快一倍多），
**且与串口打印同时进行** —— 这是"两任务并行"的直接证据。

## 5. 踩过的坑（写进文档比写在脑子里值钱）

1. **CubeMX 的 Stack Size 单位是"字"**，填 512 实际分配 2048 B。按字节理解会差 4 倍。
2. **优先级不是照着填的数**：填 24 实际生成 `osPriorityBelowNormal1`(17)，填 8 → `osPriorityLow`(8)。
   CMSIS 的 `osPriority_t` 有一组预定义序号，UI 里的数字会被映射。
3. **CubeMX 未识别手写进 `.ioc` 的 `configTOTAL_HEAP_SIZE`**，生成后仍是 3072，需手动改 `FreeRTOSConfig.h`。
4. **FreeRTOS 抢占 SysTick 后 HAL 计时会失效**，必须把 HAL Timebase 换成普通定时器（本项目用 TIM4）。
5. **`while(1)` 留在 `main()` 里是死代码**：`osKernelStart()` 不返回，后面的循环永远不执行。
   任务代码必须放进任务函数或 USER CODE 区。
